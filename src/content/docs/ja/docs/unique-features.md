Tessa は、コンポジタに別製のバー、ランチャー、通知デーモン、シェルスクリプトを
後付けした構成ではありません。コンポジタとシェルを最初から一緒に設計している
ため、本来は別々のツールに分かれる機能が同じ状態を共有できます。

このページでは、Tessa ならではの機能をまとめます。中心にあるのは
**Scene（場面）** — レイアウト、ウィンドウ、色、壁紙まで覚える名前付き
ワークスペースです。

## Scene: 作業ごと覚えるワークスペース

Scene は再利用できるワークスペースのテンプレートです。いまのワークスペースを
`coding`、`writing`、`game` として保存し、あとから同じレイアウトを組み直さずに
呼び戻せます。

```sh
tessa-ctl scene save coding
tessa-ctl scene activate coding
tessa-ctl scene apply coding 2
tessa-ctl scene list
```

Scene が保存するもの:

- レイアウトと調整値（master 比率、gaps、グリッド列、モザイク設定、
  スクロール列の幅）
- その場面に属するウィンドウ/アプリ
- ネイティブ Wayland クライアントから取得した再起動コマンド
- フローティングウィンドウの位置とサイズ
- 任意のテーマ色と壁紙

Scene の適用は**非破壊**です。対象ワークスペースに既にあるウィンドウは残し、
不足しているアプリだけを起動します。新しく開いたウィンドウは Scene に照合され、
そのワークスペースへ配置されます。破壊的なセッションリセットではなく、
繰り返し使えるテンプレートです。

### Scene デッキ

`Super+Shift+Tab` で Scene デッキを開きます。各カードには Scene 名、
ワークスペース、レイアウト、アプリ数/ライブウィンドウ数、最大4枚の
ライブプレビューが表示されます。`Tab` / `Shift+Tab` または矢印で移動し、
`Enter` / `Space` / クリックで適用、`Esc` で閉じます。

プレビューは Alt+Tab スイッチャーと同じオフスクリーンキャプチャを使うため、
非表示ワークスペースのウィンドウも表示できます。

### Scene ごとの色と壁紙

Scene は独自の視覚レイヤーを持てます:

```ini
[theme]
accent = #7aa2f7
bg = #070b14
border_active = #7aa2f7
border_inactive = #26324a
panel_bg = #0e1626
panel_fg = #e8eefc

[wallpaper]
image = ~/Pictures/Wallpapers/indigo.png
fit = cover
```

Scene が有効な間、コンポジタはそのワークスペースのウィンドウ枠と背景色を
Scene の色にし、その出力のパネルは Scene の各面の色と壁紙へ切り替えます。
Scene のないワークスペースへ移動すると、基本テーマと壁紙へ戻ります。
出力ごとに別々の Scene を表示できます。

作業ごとに「部屋」が変わるような切り替えを、セッションを分けずに実現できます。

### 知っておきたい制約

Scene は意図的にベストエフォートです:

- XWayland（`xwayland-satellite` 経由）のウィンドウはウィンドウ単位の PID が
  ないため、app-id/title で照合するだけで自動再起動はできません
- タイル順、タブグループ、Scrolling のカラム構造は近似です。フローティングの
  ジオメトリは復元します
- 適用は非破壊なので、別 Scene のウィンドウが同じワークスペースに残る場合が
  あります。きれいに切り替えたい場合は別の WS を使ってください
- コマンド引数に機密情報が入る可能性があるため、Scene ファイルは 0600 です

詳しいリファレンスは [ガイド](/ja/docs/guide/#scene) と
[カスタマイズ](/ja/docs/customization/#scene) にあります。

## 統合されたシェル

バー、ランチャー、通知サービス、トレイ、メディア操作、オーディオカード、
コントロールセンター、壁紙、ウィンドウスイッチャーは Tessa の一部です。
Waybar/Rofi/mako を組み合わせる作業も、別プロセスのテーマ管理も不要です。

この統合があるからこそ Scene が成立します。レイアウト状態、ウィンドウ状態、
テーマトークン、パネルが同じシステムにあるためです。

## レイアウトが第一級

Tessa は1つのタイルモデルではなく、複数のレイアウトを持ちます:

- master/stack
- mosaic
- grid
- Scrolling カラム
- Monocle
- Deck Stacking
- 外部レイアウトヘルパー

レイアウトと調整値はワークスペース単位で、`Super+T` で巡回でき、出力ごとに
別々に保持されます。Scene はその実効状態をまるごと保存します。

## デスクトップ全体のライブプレビュー

`Alt+Tab` は**全出力・全ワークスペース**の MRU スイッチャーを開きます。
ネイティブウィンドウはサブサーフェスを含めて専用のオフスクリーン GPU シーンへ
ライブ描画され、パネルへ転送されます。非表示ワークスペースのウィンドウも
プレビューされ、カードごとにぼかし背景が付きます。

Scene デッキも同じキャプチャ経路を使っています。

## 色文字列ではなくテーマシステム

Tessa の意味論ロール（`accent`、`window.border.*`、`panel.*`、`bar.*`、
`launcher.*`、`popover.*`、`toast.*`、`wallpaper.*`）はコンポジタとパネルで
共有されます。統合コントロールセンターの THEME ページからパレット、
アクセント、ベーストーンを変更でき、`theme-colors.conf` 経由で枠、パネル、
壁紙をまとめて再読み込みします。

Scene はこれをさらに一歩進め、ワークスペースごとに色を変えられます。

## 日本語ファーストの細部

日本語は後付けではありません:

- ロケールを考慮した CJK フォントフォールバックで JP 字形を選択
- Fcitx5/Mozc 連携（text-input-v3 と XIM）
- 日本語ドキュメントと日本語を前提にした既定環境
- 翻訳文字列だけでなく、日本語の表示を考えた UI とタイポグラフィ

## パネルはTessaの外でも動く

Tessa Panel は互換ブリッジ経由で Hyprland、Niri、その他の layer-shell
コンポジタでも動きます。この構成はまだ実験的ですが、シェルが Tessa の
コンポジタに永久に縛られないことを示しています。

## まとめると

| よくある構成 | Tessa の考え方 |
| --- | --- |
| コンポジタ + Waybar + Rofi + mako + スクリプト | コンポジタとシェルを一緒に設計 |
| ワークスペースのレイアウトを一度設定 | WS ごとのレイアウトと実行時巡回 |
| タイトルやスクリーンショットのスイッチャー | 全 WS のライブ GPU プレビュー |
| コンポジタとバーで別々のテーマ | 共有トークンとテーマエディタ |
| スクリプトでWSテンプレートを再現 | アプリ・色・壁紙まで持つ Scene |
| フォントフォールバックだけの日本語対応 | フォント、IME、ドキュメントまで日本語ファースト |

Tessa はまだ若いプロジェクトです。ここに挙げたのは方向性であり、すべての
エッジケースが完成したという主張ではありません。
[既知の制限](/ja/docs/#既知の制限) と [ロードマップ](/ja/docs/roadmap/) も
合わせて確認してください。
